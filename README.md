# The Signal — News Aggregator

Проект по Software Design Patterns на Java с необязательным веб-интерфейсом. The Signal объединяет RSS и JSON в одну новостную ленту. HTTP API отдаёт статьи, поддерживает поиск, фильтры и сортировку и уведомляет подписчиков об обновлении ленты. Можно запустить только бэкенд или бэкенд вместе с интерфейсом.

## Запуск

На Windows распакуйте ZIP и выберите один из двух файлов:

| Файл | Режим запуска |
| --- | --- |
| **START.cmd** | Бэкенд и веб-интерфейс: открывает новостную ленту с поиском, фильтрами, сортировкой и переключением Demo / Live. |
| **START_BACKEND.cmd** | Только бэкенд: открывает JSON по `/api/feed`. Веб-интерфейс в этом режиме недоступен. |

Оба файла собирают проект и выбирают свободный порт. Держите окно запуска открытым; для остановки закройте его или нажмите `Ctrl+C`. Дополнительный Node.js, npm или отдельный сервер для интерфейса не нужен.

**Сначала извлеките весь архив:** нажмите правой кнопкой на ZIP → «Извлечь всё…», затем откройте полученную папку `news-aggregator`. Запуск из окна просмотра ZIP не работает: Windows может извлечь только выбранный `.cmd`, оставив остальные файлы внутри архива. Рядом с файлами запуска должны находиться `start.ps1`, `run.ps1` и папка `src`.

Понадобится JDK 17 или новее. Команды `java` и `javac` должны быть доступны в системе. Для ручного запуска откройте PowerShell в распакованной папке проекта:

```powershell
# Только API
.\run.ps1

# API и веб-интерфейс
.\run.ps1 -Web
```

Сервер по умолчанию слушает `http://127.0.0.1:8080/`. При ручном запуске откройте этот адрес самостоятельно; список API доступен по `/api` в обоих режимах. Если порт занят, укажите другой через `.\run.ps1 -Port 8081 -Web` или используйте `-Port 0` для свободного порта. Для остановки нажмите `Ctrl+C` в терминале. Если PowerShell блокирует локальный скрипт по политике исполнения, используйте `powershell -ExecutionPolicy Bypass -File .\run.ps1 -Web` для этого запуска.

На Linux и macOS из корня проекта:

```sh
mkdir -p build/classes
find src/main/java -name '*.java' -print > build/sources.txt
javac --release 17 -encoding UTF-8 -d build/classes @build/sources.txt
java -cp build/classes:src/main/resources newsaggregator.Main
# Для интерфейса добавьте --web (при необходимости порт перед флагом):
java -cp build/classes:src/main/resources newsaggregator.Main 8080 --web
```

Режим `demo` запускается автоматически и загружает 10 вымышленных статей из локальных RSS и JSON. Режим `live` загружает BBC News World RSS и DEV Community JSON. Если один источник не отвечает, API возвращает его статус ошибки вместе со статьями доступного источника.

В веб-интерфейсе можно искать новости, выбирать источник и категорию, менять сортировку и обновлять ленту. Демо-статья открывается в окне с её описанием; Live-статья ведёт на сайт источника. SSE автоматически обновляет открытую ленту после изменения данных, сохраняя фильтры. Demo / Live относится к данным, а выбор файла запуска — к наличию интерфейса: это независимые настройки.

## HTTP API

| Запрос | Результат |
| --- | --- |
| `GET /` | Веб-интерфейс при `-Web`; список маршрутов в JSON при запуске только API. |
| `GET /api` | Список доступных маршрутов в JSON в обоих режимах. |
| `GET /api/feed` | Версия ленты, статьи и статусы источников. Параметры `q`, `category`, `source` и `sort` управляют выдачей. |
| `POST /api/refresh?mode=demo` | Обновляет ленту и повышает номер версии. Для внешних источников используется `mode=live`. |
| `GET /api/events` | Поток Server-Sent Events. Событие `feed` содержит `revision` и `mode`. |
| `GET /demo/{slug}` | Данные отдельной демо-статьи в JSON. |

Параметр `sort` принимает `latest`, `oldest` или `title`; пустое или неизвестное значение означает `latest`. Идентификаторы источников — `bbc` и `dev`. Категории: `world`, `technology`, `science`, `business`, `culture`, `other`. Для `source` и `category` пустая строка или `all` отключает фильтр; неизвестное значение даёт пустую выдачу. Фильтры и поиск не зависят от регистра. `q` ищет подстроку в заголовке, описании, названии источника и тегах.

`sources[].count` — число принятых статей конкретного источника до общей дедупликации и фильтрации запроса. Поэтому сумма этих счётчиков может отличаться от размера `articles`. Ошибка одного источника не мешает загрузить другой. Внешняя загрузка ограничена четырьмя секундами на весь ответ и размером 2 MiB для каждого источника.

## Что показать на защите

После запуска сервера откройте отдельный PowerShell. Ниже указан порт 8080 для ручного запуска; при запуске через `.cmd` замените его на порт из окна сервера. Проверьте источники, затем покажите результат поиска с категорией и тегами.

```powershell
$api = 'http://127.0.0.1:8080'
(Invoke-RestMethod "$api/api/feed").sources | Format-Table name, format, count, state
(Invoke-RestMethod "$api/api/feed?source=dev&category=technology&q=accessibility").articles |
    Select-Object title, category, tags
```

Для Strategy сравните порядок заголовков одного источника при двух значениях `sort`.

```powershell
(Invoke-RestMethod "$api/api/feed?source=bbc&sort=latest").articles.title
(Invoke-RestMethod "$api/api/feed?source=bbc&sort=title").articles.title
```

Для Observer оставьте поток событий открытым в отдельном терминале. При запуске потока придёт текущая версия.

```powershell
curl.exe -N http://127.0.0.1:8080/api/events
```

Отправьте `POST` из терминала с `$api`. В потоке событий появится `feed` с новым номером `revision`. Тот же запрос с `mode=live` покажет загрузку из внешних источников, если есть интернет.

```powershell
Invoke-RestMethod -Method Post -Uri "$api/api/refresh?mode=demo" |
    Select-Object mode, revision
```

При демонстрации Live проверьте статусы: новая версия сама по себе не означает, что внешние источники успешно загрузились.

```powershell
(Invoke-RestMethod -Method Post -Uri "$api/api/refresh?mode=live").sources |
    Format-Table name, format, count, state
```

### Как объяснить диаграммы вдвоём

Начните с [общей диаграммы проекта](docs/project-class-diagram.svg). HTTP-клиент обращается к `NewsServer`, а сервер вызывает `NewsFacade`. Фасад получает статьи из источников, собирает снимок ленты, затем передаёт его `FeedPublisher` для рассылки события.

| Участник | Паттерн | Реализация и роль |
| --- | --- | --- |
| 1 | Adapter | `RssNewsAdapter` и `JsonNewsAdapter` приводят записи разных форматов к общей модели `Article`. Оба реализуют `NewsSource`. |
| 1 | Factory Method | `NewsSourceFactory.forMode` выбирает адрес для Demo или Live. Конкретные фабрики реализуют `create` и создают свой адаптер. |
| 1 | Decorator | `CategorizedArticle` оборачивает `Article`, вычисляет категорию по тегам источника или значению по умолчанию и делегирует чтение остальных полей. |
| 2 | Strategy | `NewsFacade` выбирает через `SortStrategy` порядок `LatestFirst`, `OldestFirst` или `TitleOrder` для результатов запроса. |
| 2 | Observer | `FeedPublisher` уведомляет подписчиков после сохранения нового снимка. HTTP-клиенты получают номер версии через SSE и могут запросить обновлённую ленту. |
| 2 | Facade | `NewsFacade` даёт HTTP-слою единый вход для обновления, запроса и подписки. |

**Участник 1** по [своей диаграмме](docs/participant-1-class-diagram.svg) прослеживает путь от фабрики до готовой статьи. Покажите RSS и JSON в поле `sources`, затем ответ на запрос с `category=technology` и объясните, откуда взялись категория и теги.

**Участник 2** по [своей диаграмме](docs/participant-2-class-diagram.svg) прослеживает запрос и обновление через `NewsFacade`. Покажите смену сортировки через `sort` и изменение `revision` в открытом потоке после `POST /api/refresh`.

### Связь с лекциями SDP

В [лекции 2](https://lms.astanait.edu.kz/mod/resource/view.php?id=73143) роли Factory Method соответствуют `NewsSourceFactory` (Creator), двум подклассам фабрики (Concrete Creators), `NewsSource` (Product) и адаптерам (Concrete Products). Фабричный метод здесь — переопределяемый `create`; выбор Demo/Live в `forMode` только определяет адрес.

В [лекции 3](https://lms.astanait.edu.kz/mod/resource/view.php?id=73144) используется Object Adapter: `NewsSource` — Target, `RssFeedReader` и `DevApiClient` — Adaptees, а адаптеры вызывают их методы и преобразуют результат для клиента `NewsFacade`. Это преобразование интерфейса. `CategorizedArticle` сохраняет интерфейс `Article` и расширяет поведение его `category()` и `tags()` — различие, нужное для объяснения Decorator из [лекции 5](https://lms.astanait.edu.kz/mod/resource/view.php?id=73146).

В учебной UML Decorator может быть разделён на абстрактную обёртку и конкретные декораторы. Здесь один `CategorizedArticle` совмещает эти роли: хранит компонент типа `Article`, сам реализует `Article` и делегирует неизменяемые операции. При появлении нескольких декораторов общую часть можно вынести в отдельный базовый класс.

`NewsFacade` упрощает доступ к нескольким подсистемам, как Facade из [лекции 6](https://lms.astanait.edu.kz/mod/resource/view.php?id=73147). Для Strategy из [лекции 7](https://lms.astanait.edu.kz/mod/resource/view.php?id=73148) фасад служит контекстом: каждый запрос выбирает неизменяемую стратегию и получает её `Comparator`. Меняется политика сравнения, а вызов сортировки остаётся общим. В лекции также приведён пример Strategy через `Comparator`; общий изменяемый setter для параллельных HTTP-запросов не нужен.

Для Observer из [лекции 8](https://lms.astanait.edu.kz/mod/resource/view.php?id=73149) `NewsFacade` хранит состояние, а `FeedPublisher` управляет подпиской и рассылкой — как разделение Editor/EventManager в лекции. Общий интерфейс наблюдателя — `Consumer<FeedSnapshot>`, его метод обновления — `accept`. Обработчик SSE подписывается, получает снимок и отписывается при завершении соединения. Уведомление идёт после сохранения снимка; вложенный `refresh` из callback запрещён, чтобы подписчики не получали версии в обратном порядке.

Шесть паттернов работают в одном потоке обработки. Builder, Abstract Factory, Bridge и другие темы курса не заявлены как дополнительные реализованные паттерны. Распределение 3 + 3 — план объяснения; перед сдачей укажите фактический вклад каждого участника.

## Проверка

```powershell
.\run.ps1 -Test
```

Тесты проверяют загрузку обоих форматов, маркировку, фильтры, сортировку, дедупликацию, изоляцию ошибки источника, некорректные данные, лимит размера и общий таймаут загрузки, ответы HTTP и получение новой версии двумя SSE-подписчиками. Проверка запрещённого вложенного обновления защищает порядок версий. Для прогона достаточно JDK: сетевые пограничные случаи используют временный сервер на loopback и не требуют интернета. Live проверяется отдельно, поскольку результат зависит от сети и текущего содержимого источников.

HTTP-проверки запускают сервер в обоих режимах: проверяют одинаковый API, загрузку HTML/CSS/JavaScript в режиме `-Web`, недоступность веб-файлов при запуске только API, типы содержимого и защиту от выхода за список разрешённых файлов.

## Структура

- `src/main/java/newsaggregator/core` — модель и реализация шести паттернов.
- `src/main/java/newsaggregator` — запуск, HTTP-маршруты, выдача JSON/SSE и необязательная раздача веб-интерфейса.
- `src/main/resources/feeds` — локальные демо-данные в RSS и JSON.
- `src/main/resources/web` — HTML, CSS, JavaScript и локальные изображения интерфейса; используются только в режиме `-Web`.
- `src/test` — автономный тестовый сценарий.
- `docs` — UML, скриншоты и исходник генератора PDF-отчёта.
